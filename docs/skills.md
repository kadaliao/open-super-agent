# 技能

技能是一套可复用的做事方法：做哪几步、用哪些网站或应用、结果写成什么样。它是交给 Bot 照着做的说明，不是代码。

- 用户在对话里输入 `/名字`（可以接着写补充要求）调用，做法附在这条消息后面交给 Bot。
- 用户没写 `/名字`，但要做的事正好归某个技能管时，Bot 自己用 `use_skill` 取做法再照着做。系统提示词里只列技能的名字和一句话说明，
  做法要用时才取，技能多了也不会让每轮对话变长。
- 定时任务、事件可以绑一个技能，每次运行按它做。

技能在右栏 **技能** 里管理：新建、编辑、导入、导出、分享，从 **技能市场** 装现成的，或者点 **演示一遍** 在电脑上做一次让 Bot 整理成技能。
也可以在对话里说“把刚才的做法存成技能”。每个 Bot 最多 100 个技能；勾上“所有 Bot 都能用”的是共用技能，同名时 Bot 自己的优先。

## 写法

一个技能就是一个 `SKILL.md`：开头一段 YAML，后面是做法（Markdown）。

```markdown
---
name: 周报整理                # /周报整理 调用；中文、字母、数字、- 和 _，最长 40 个字
description: 把这一周做过的事整理成周报，存进资料库   # 一句话说明什么时候用，Bot 靠它判断要不要用这个技能
apps: [notion]                # 可选：要用的应用（应用市场里的名字）
---

1. 定范围：默认是本周一到今天……
2. 用 search_memory 查资料库里这段时间的页面……
3. 用 save_page 存成页面，回复里附上链接。
```

- 做法最长 2 万字。写清楚步骤、要用的工具或应用、输出格式和“没有材料时怎么办”，不要写这一次的具体数据。
- 要用应用时在做法里写 `@应用名`（比如“记到 @notion”），派任务时 Bot 会原样带上，Worker 就知道用哪个应用。
- `apps` 写了就以它为准（写 `apps: []` 表示不用应用）；没写时按做法里的 `@应用名` 找。导入时会把没连接的应用列出来，点“去连接”。
- 做法里别写密码、token：分享出去别人能看到。密钥放进设置里的保险库，应用自己去取。

## 带文件的技能包

和 Claude 的 Agent Skills 一样，技能可以带文件：`scripts/` 里的脚本、`references/` 里的参考资料、模板……

```
fill-form/
  SKILL.md
  scripts/fill.py
  references/fields.md
```

- 只收 UTF-8 文字文件：最多 50 个、合计 20 万字；图片、字体、PDF 这类导入时跳过并列出来。以 `.` 开头的（`.git`、`.env`）、`__MACOSX` 不收。
- Bot 用 `use_skill(name)` 取做法时，附上文件清单和每个文件开头 400 字（文件多时只附前面几个的）；要看全文用 `use_skill(name, file="scripts/fill.py")`，
  太长的分段给（`offset`）。
- 要运行脚本，Worker 用 `computer_write_file` 把文件写进电脑的工作文件夹，再用 `run_code` 或 `computer_shell` 跑。
  Router 自己跑不了脚本，会派任务。所以做法里写清楚“跑 scripts/fill.py，参数是……”就行，不用写怎么把文件放进电脑。
- 编辑器里能点开每个文件看内容、去掉不要的文件；文件内容在编辑器里改不了，要改就改好了重新导入。

## 导入、导出、分享

- **导出**：编辑器下面的 **导出文件**。没带文件的是一个 `<名字>.md`；带了文件的是 `<名字>.zip`，`SKILL.md` 在根上，文件按相对路径放。
- **导入**：右栏 **技能** → **导入**，可以：
  - 选一个 `.md` 或 `.zip` 文件。别处打的 zip 常常外面包了一层文件夹，也认（名字没写就用文件夹名）。
  - 粘贴链接：别人分享的 `…/skill/<token>`；GitHub 上的 `SKILL.md` 或技能文件夹（`https://github.com/<owner>/<repo>/tree/<分支>/<路径>`）。
    文件夹会用 GitHub 的接口列出里面的文件（往下最多 3 层）逐个取；GitHub 限制了没登录时的访问次数（每小时 60 次），
    超了就只取 `SKILL.md`，并提示其他文件没取到。
  - 导入后先打开编辑器给你看一遍，保存了才生效：技能是 Bot 照着做的指令，带脚本的还会在电脑里运行，别装来路不明的。
- **分享**：**生成分享链接** 得到一个不可猜的 `/skill/<token>`，拿到链接的人能看到做法和文件清单，能导入到自己的 open-super-agent；
  带文件的技能，链接下载到的是 zip。**取消分享** 后链接失效。
- 导出 Bot 模板（见 [写一个 Bot 模板](templates.md)）时，技能带的文件和 `apps` 也一起写进模板。

## 技能市场

右栏 **技能** → **技能市场** 列出随 open-super-agent 发布的技能，点 **安装** 复制一份给这个 Bot（来源记成“技能市场”），之后能照常改；
已经有同名的会问一句再替换。现在有三个，都只用现成的工具：

| 文件夹 | 技能 | 做什么 |
|---|---|---|
| `weekly-report` | /周报整理 | 把这一周做过的事整理成周报，存进资料库 |
| `save-webpage` | /存网页 | 把网页正文转成干净的 Markdown 存进资料库，留下来源链接 |
| `meeting-notes` | /会议纪要 | 把会议记录整理成结论、待办（谁、什么时候）、没定下来的问题 |

想加一个：在 `osa/catalog/skills/<名字>/` 里放 `SKILL.md`（中文界面装的）和 `SKILL.en.md`（英文界面装的，可选，名字和说明都用英文），
要带的文件放在同一个文件夹里，提 PR。文件夹名只用小写字母、数字和 `-`。`tests/test_skills.py` 会检查每个技能中英文都能读出来。

## 和 Claude 的 SKILL.md 兼容

- 格式一样：开头的 YAML 加 Markdown 做法，`scripts/`、`references/`、`assets/` 这些文件夹原样带着。Claude 的技能包能直接导入；
  这里导出的 zip 解开就是一个技能文件夹的内容，放进以技能名命名的文件夹（比如 `~/.claude/skills/<名字>/`）就能给 Claude 用，
  名字要符合 Claude 的规则（小写字母、数字和 `-`）。
- 认的键：`name`、`description`、`apps`。`license`、`allowed-tools`、`metadata` 这类别的键导入时忽略，导出时不会写回去。
- 名字里的空格、点换成 `-`，去掉不能用的字；没写 `name` 时用文件名或文件夹名，再没有就用做法的第一个 `#` 标题。
- 不一样的地方：Claude 按 `description` 自己决定加载哪个技能、在自己的沙箱里跑脚本；这里 Bot 也是看名字和说明决定用不用，
  但脚本要写进电脑的工作文件夹才能跑（Docker、Instabox 的电脑，或者本机的工作文件夹），没有电脑时脚本跑不了。
  二进制文件（图片、字体）不收，用到它们的技能导入后要自己补上。
