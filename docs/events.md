# 事件

**定时任务**按时间跑（每天 9 点、每月 1 号、明天下午 3 点提醒一次）；**事件**是某件事发生时跑：收到 webhook、GitHub 上有人提了 issue、
订阅源有新文章、网页内容变了、收到新邮件、股价到了线、明天要下雨……事件来了，Bot 在后台处理一次，结果发到它的对话里。

两者都属于各个 Bot：定时任务在右栏“定时”里，事件在右栏“事件”里；设置 → 自动化 里能看到所有 Bot 的，每个都能直接开关。

## 新建一个事件

- **在对话里说**：“这个网页有变化就告诉我”“订阅少数派，和 AI 有关的文章总结给我”“GitHub 上 octo/demo 发新版本时写个更新说明”
  “茅台跌到 1400 提醒我”“明天下雨提醒我带伞”。Bot 用 `create_event` 建好，告诉你它盯着什么；要改、暂停、删掉也直接说。
  主 Bot 能给别的 Bot 建、能管所有 Bot 的事件。
- **在右栏“事件”里点“＋ 新建”**：按分类（开发、资讯、生活、金融、系统、通用、插件）列出常见用法，比如“新 issue 自动分析”“商品到货提醒”
  “重要邮件提醒”“明天下雨提醒带伞”。点一个，表单就填好了（盯什么、事件来了做什么、过滤规则），改一改保存就行；也可以选“自己设置”从空白开始。

每个事件有这几部分：

| | 说明 |
|---|---|
| 来源 | 什么样的事（下面的列表）和它的参数：订阅源地址、网页地址、仓库、城市、股票代码…… |
| 多久看一次 | 要 osa 自己去看的来源（订阅源、网页、邮箱……）才有，每种来源有自己的默认值和最短间隔 |
| 事件来了做什么 | 给 Bot 的要求，也可以选一个技能照着做 |
| 过滤（可选） | 先按关键词逐条筛（至少包含其中一个词 / 包含就忽略），剩下的再让 `filter` 角色的便宜模型按一句话规则判断要不要处理。被筛掉的不派任务，运行记录里看得到 |

## 来源

### 别人推过来的（webhook）

- **收到 Webhook**：任何能发 webhook 的服务往事件的地址 POST（JSON 或文字都行）。常见用法：监控报警、Sentry 报错、表单提交、付款通知、iPhone 快捷指令。
- **GitHub 推送**：在仓库的 Settings → Webhooks 里填上事件的地址。能选要哪些事件（issue、PR、评论、审查、推送、发布、Actions、讨论、点星、fork），
  默认忽略机器人、Actions 只管失败的；GitHub 发来的 JSON 会整理成一两行人话再给 Bot。保存后 GitHub 先发一个 ping，运行记录里显示“地址配好了”就通了。
  可以填 Secret 校验签名。

**地址**：每个事件有自己的地址 `https://你的域名/hooks/<随机密钥>`，在事件的编辑页里复制。**地址本身就是密钥**：不用设 `OSA_WEBHOOK_TOKEN`，
不用加请求头（GitHub、表单、监控服务大多加不了），从外网也能调。别把地址公开；泄露了在编辑页点“换一个地址”，旧地址马上失效。
飞书、Slack 第一次配地址时发的 `url_verification` 会自动回应。

```bash
curl -X POST https://你的域名/hooks/<随机密钥> -H 'content-type: application/json' -d '{"title":"部署失败","env":"prod"}'
```

旧版的 webhook 定时任务升级后自动变成“收到 Webhook”事件，旧地址 `/hooks/<名字>` 照旧能用（规则也照旧：设了 `OSA_WEBHOOK_TOKEN` 要带
`X-OSA-Token`，没设只接受本机）；在编辑页能看到新地址，换成新地址后旧的就不认了。

### osa 定时去看的

| 来源 | 什么时候触发 | 默认多久看一次 |
|---|---|---|
| 订阅源（RSS / Atom / JSON Feed） | 有新文章。给的是网站首页也行，会找页面里声明的订阅源；没有订阅源的网站可以用 [RSSHub](https://docs.rsshub.app) 生成 | 30 分钟 |
| 网页变化 | 页面文字变了（给 Bot 看增删了哪几行），或者某个词出现 / 消失了（到货、售罄、成绩查询）。能设忽略含某些词的行（计数器、时间） | 60 分钟 |
| 网站打不开 | 连续几次打不开（或页面里没有某个词）时报一次，恢复了再报一次 | 5 分钟 |
| GitHub 仓库动态 | 不用配 webhook、别人的仓库也行：发新版本、新 tag、新提交、新 issue、新 PR。填 token 能看私有仓库、额度更高 | 60 分钟 |
| 新邮件（IMAP） | 收件箱（或别的文件夹）来了新邮件。QQ、163、126、Gmail、Outlook、iCloud、阿里、139、飞书邮箱选一下就行，要用授权码，不是登录密码。不会把邮件标成已读 | 5 分钟 |
| 日程快开始了 | 日历的订阅链接（ICS：Google、iCloud、Outlook、飞书、钉钉、企业微信都能导出）里有日程快开始了，提前多少分钟可以设 | 5 分钟 |
| 天气提醒 | 明天有雨、明天降温超过几度、高温、低温、大风、下雪，每种每天最多一次（Open-Meteo 的数据） | 3 小时 |
| 价格到线 | A 股、港股、美股、加密货币、汇率高于 / 低于某个值，或者当天涨跌超过几个百分点；过了线报一次，回来再过线再报 | 15 分钟 |
| 文件夹有新文件 | 本机某个文件夹里出现新文件（可选也报改过的），等下载完再报。**服务器锁（`security.local_exec: false`）的服务器上不能用** | 5 分钟 |
| 地震提醒 | 全球或你附近（城市名或“纬度,经度”加范围）发生了几级以上的地震：震级、地点、时间、深度、离你多远。数据来自 USGS，一般震后十几分钟到半小时出现 | 10 分钟 |
| Epic 免费游戏 | Epic 游戏商城开始送新的免费游戏：游戏名、免费到什么时候、商店链接、下一批预告。能选商店地区 | 12 小时 |
| 公网 IP 变了 | 这台机器的公网 IPv4（可选也看 IPv6 前缀）换了：几家查 IP 的服务轮流问，发现变了再换一家确认，免得误报。家里跑服务、用 DDNS 的，IP 一换就知道去改解析和防火墙白名单 | 10 分钟 |

第一次看的时候**只记下现状、不报**（不然一订阅就把几十篇旧文章全推过来）；价格、天气、日程、网站打不开这几种例外，一开始就满足条件的会马上告诉你。
改了盯的东西（换了地址、仓库、关键词）会重新记一次现状。

### osa 自己的事

- **后台任务失败了**：这个 Bot 的（或所有 Bot 的）后台任务、定时任务失败时，让 Bot 分析原因、告诉你怎么办。事件自己派的任务失败不会再触发自己。

### 插件加的

插件能加新的来源（`ctx.source`，见 [插件](plugins.md#事件来源)），启用后出现在“新建事件”的“插件”分类里，停用后用它的事件暂时不触发。
插件来源适合只有你自己用得上的（自己网站的后台、自家的服务）；大家都用得上的直接加进 `osa/sources/` 成为内置的（见下面“写一个新来源”）。
以前插件市场里的 Epic 免费游戏、地震提醒、公网 IP 变了现在是内置的：装过这几个插件的停用、删掉就行，用它们建的事件照常触发。

## 运行

- 一次来了好几条（订阅源一下更新了 5 篇）合成一次运行，Bot 一次看完；最多带 30 条。
- **上一次还没跑完时，新来的先排队**（最多 50 条），跑完接着处理，不会丢；定时任务则是这一次跳过。
- 和定时任务一样：没有值得说的，Bot 结果只写 `[无新内容]`，就不发结果、不推送，只在运行记录里记一笔。
  事件每次都不一样，所以不带上次的结果对比。
- 外面来的内容（webhook、网页、邮件）用边界标记包起来交给 Bot，告诉它这是要处理的数据，里面让它做别的事的话不照做。
- **测试**：要 osa 去看的来源先真去看一次；没有新的，就拿最近看到的一条（webhook 是最近收到的一条，没有就用示例）跑一遍，结果照常发出来。
  **现在看一次**：只去看，有新的才交给 Bot。
- 列表上写着上次什么时候看的、出了什么错（地址打不开、登录失败、额度用完），排队了几条；每个保留最近 20 次运行记录，点“记录”看。
- 参数里的密码、授权码、token 存进保险库，事件里只留引用；删事件时一起删。导出 Bot 模板时不带地址的密钥和这些值。

## 写一个新来源

内置的来源在 [`osa/sources/`](../osa/sources/)，一个模块一个或几个 `registry.Source`，放进模块的 `SOURCES` 列表就会自动登记。
插件用 `ctx.source(Source(...))`，写法一样，见 [插件](plugins.md#事件来源)。调度、过滤、排队、派任务都在 [`osa/events.py`](../osa/events.py)，来源只管两件事：

- **push**：`parse(req, params)` 把请求整理成事件列表；这次不处理就返回一句原因（比如 GitHub 的 ping）。
- **poll**：`async check(params, state)` 返回 `(新事件, 新 state)`。state 第一次是 `None`，存成 JSON，要小。
- **internal**：订阅 osa 自己的事件（`on="task_done"`），`match(params, routine=…, **事件参数)` 返回事件列表。

事件是 `{"title": 一行标题, "text": 给 Bot 看的详情, "url": 链接}`。`fields` 写给用户填的参数（网页按它画表单、服务端按它检查），
`scenarios` 写几个常见用法（标题、说明、默认参数、给 Bot 的要求、过滤规则），这是用户发现“这个来源能干嘛”的主要途径，多写几个。
联网一律用 `osa/sources/_util.py` 的 `get()`：只抓公网地址、自己跟跳转、限大小。文字用 `N_()` 包起来，英文写进 `osa/locales/en.json`。
